## 二、原始产品功能清单

目标用户为备考计算机 408 的大学生。首版验证“哪里薄弱、下一步做什么、做完有何变化”，起始范围为数据结构部分章节。学生拥有个人资料和作答；维护者发布公共内容；管理员管理服务、角色与运维；外部模型提供待校验的候选或建议。规划为 2026 年 12 月首版、30–50 名学生试用，实际日期、人数和冻结章节以试用记录为准。[问题定义](problem_definition.md) · [功能规范及领域模型](functional_spec.md)

## 四、诊断、知识状态、推荐的计算要求

| 步骤 | 原设计和对接时确定的行为 |
|---|---|
| 1. 建立诊断 | 根据选定范围、知识点、认知目标、发布题库存建立轮次和分段，创建时排好题。诊断可探测尚缺先修证据的点。上一题作答影响后续状态和任务安排；当前轮内没有逐题计算信息量再改选下一题的 CAT 要求 |
| 2. 确定证据 | 保留全部作答历史；诊断计算排除无效或停用版本。按最近 14 天及独立轮次覆盖边界取有效记录，同一稳定题 ID 取首次有效答题。重做能更新最近活动时间。独立复测只更新参与知识点与维度的证据边界 |
| 3. 计算知识点状态 | 按先修图拓扑顺序处理。不同题数少于 3 为证据不足；达到 3 题、正确率 ≥80%、所有直接先修均初步掌握时为初步掌握，其余达到题量的情形为待巩固。根节点无需先修。策略标识为 `baseline-0.1` |
| 4. 计算认知表现 | 各“知识点 × 认知标签”分别显示去重后的样本数、正确率、最近作答时间和证据充足性。理解表现充分不能代替应用证据。标签描述解题必需的思维活动，难度另记 |
| 5. 选择下一任务 | 先过滤先修、发布与访问权限，再按待巩固、证据不足、进一步应用／复习排序；同级考虑维度缺口、近期练习，未练及较久未练题优先。指定目标无题要揭示库存缺口。保存策略、图版本、证据摘要及选择理由 |
| 6. 执行与调整 | 接受后进入资料或练习，可跳过／更换；按版本判分后给静态解析、认知要求与下一安排。当前原型以近期两道不同应用／分析题错误触发回看资料。该触发值待验证 |
| 7. 复习后复测 | 阅读只更新任务状态。下一轮优先选另一组同目标题，库存不足显示复用与记忆干扰。对比前后表现时保留证据不足的维度 |
| 8. 课程进度单独计算 | 课程掌握按新版最终小测判定。2026-11-26 已确认先修按 mastery-v2：三题全部答错保留完成记录，后继保持锁定；重练使各题最近一次结果达到 2/3 即满足该前驱的条件 |

详细依据见[规则基线](../algorithm/baseline.md)、[独立诊断与任务生命周期](../software/design_aligned_workflow.md)、[交接规则](../software/backend_handoff_objects_408.md)。先修 DAG 是当前可解释的工程基线。完整知识空间状态族、概率推断及教学有效性仍属不同研究问题。

## 五、408 后端交接 v1.5 与前端职责

本节适用于课程目录、预设练习和最终小测。接口前缀为 `/api/v1`。字段全表、错误返回和请求样例分别见[对象交接](../software/backend_handoff_objects_408.md)、[实现对照](../software/apifox_api_408_implementation_check.md)和[OpenAPI](../software/openapi.json)。

| 编号 | 必须满足的契约与验收动作 |
|---|---|
| 408-01 课程对象 | 四科 → 所属章节 → 知识点，稳定 ID、排序、发布状态明确；知识点携带直接前驱、内容标签和预设集合 ID、版本、题目键。公共内容与个人进度分别查询。地图坐标和章节顺序不决定先修 |
| 408-02 发布 | 后端校验章节归属、跨章／跨科引用、DAG、题目版本、集合和标签。保持当前固定图配置及 graph_version 可追踪，v1.5 未要求历史关系变更后的进度迁移 |
| 408-03 题目对象 | 第一阶段支持纯文本单选、2–8 个稳定选项、一个主知识点、可选关联点。区分内容标签、Bloom、难度与来源。只有审核发布的公共题可分配。学生作答前返回 QuestionPublic，提交后才显示该题答案、解析与版本 |
| 408-04 题库分离 | 预设题固定版本；个人试卷动态题标记 AI 生成并仅供本人。演示资源显式导入。仓库资源包为四科、24 章、203 个知识点、650 道题、325 条关系；内容来源与审核状态随条目保留，资源计数不能证明人工审核率 |
| 408-05 预设练习 | 只读请求返回完整有序集合，不创建任务。实际作答创建或恢复本人任务，新建 201、恢复 200，可定位下一未答。支持稳定选项 ID 与旧选项文本的兼容校验；重复请求不新增作答 |
| 408-06 完成与解锁 | 用当前版本预设题作分母，每个不同题目版本的有效提交计一次完成，答错也计，正确率独立。根节点直接开放，所有直接前驱分别完成当前非空预设集合，且每个前驱最近一次答对的不同题目数均达到本集合题数的三分之二（含等号），后继才解锁。零题节点保持 new、不可开小测，零题前驱不满足解锁 |
| 408-07 统一状态 | 细粒度 new／learning／covered／mastered 表示未练、部分、全完成、最终小测通过。摘要 locked／available／completed／mastered 中锁定优先。单点、批量、详情、地图和学习中心必须一致；客户端不能写掌握状态 |
| 408-08 建立小测 | 已解锁并完成预设集合才允许开卷。异步创建返回 202，按本人 request_id 幂等；保存试卷版本、固定题目与规则，查询列表、详情或刷新页面不会重新出题。同知识点进行中的卷禁止重复创建 |
| 408-09 判分与反馈 | 整卷一次提交，服务端按冻结答案等权计算正确题数／总题数，达到阈值才通过。先持久化分数再生成建议。历史默认 5 条、最多 20 条本人已提交记录，排除本卷；可选耗时、提示、学习目标只影响反馈。读取或模型失败时保留成绩和规则建议 |
| 408-10 事件与换版 | 整卷提交和知识点掌握事件带稳定 ID，客户端重试须去重。预设提交后重新读进度。新集合重新算完成度，仍匹配的题目键可沿用提交；旧集合的小测通过不自动继承。有进行中试卷时当前实现拒绝替换集合 |
| 408-11 接口与分工 | 地图和学习中心都从 `/subjects` 读课程结构、从 `/progress` 读用户状态。预设走 `/knowledge-points/{id}/questions`、`/tasks` 与作答接口，小测走 `/knowledge-points/{id}/ai-tests`、详情和 `/submit`。后端鉴权、算状态；前端保留学习中心 UI、处理轮询、锁定、恢复和事件展示 |
| 408-12 兼容与失败 | 新对象 snake_case、UTC ISO 时间、比率 0–1，无样本为 null，空数组为 []；旧 Unix 秒显式适配。成功直接返回业务对象。核对未登录、越权、非本人资源、锁定、冲突、非法输入、服务不可用等路径及重试后的状态 |
| 408-13 暂定参数 | 当前 API 允许题量 1–20、通过阈值 0–1，创建即冻结。目前失败可新请求重测，已通过不再开卷。正式题量、阈值、重测间隔及长期换版策略要由产品确认 |

当前后端有契约测试；新界面完整联调、正式资源发布及真实出题质量各需验收。参见[四科资源](../../resource/README.md)、[接口契约测试](../../tests/integration/test_curriculum_contract.py)。

## 九、老师补充的首次用户测试

老师消息提出两件事：开发时能解释智能体各部分如何协作；用户测试时特别关注智能体 11 项。课程学生表共 33 题。下列操作将课程题目映射到 Aristotle 的学习流程，可用于准备试用。这张清单没有代填用户分数、观察或截图。[学生版原表](https://github.com/bettermorn/ACMWDevHubPPT/blob/master/courseware/assignment/用户测试表-学生版.md) · [教师参考表](https://github.com/bettermorn/ACMWDevHubPPT/blob/master/courseware/assignment/用户测试表-教师版.md)

| 编号 | 在 Aristotle 中观察什么 |
|---|---|
| P1–P5 产品价值 | P1 首屏能否说清系统帮助决定下一步学习；P2 指出已用同类工具和替代办法；P3 用具体任务比较优劣；P4 给出推荐意愿及理由；P5 核对核心学习任务是否满足需要并列缺口 |
| I1–I4 界面设计 | I1 地图、任务、来源和设置放置是否合理；I2 计时找目标功能；I3 当前主动作是否清楚；I4 新用户能否理解题卡、标签和展开控件 |
| V1–V4 视觉设计 | V1 状态色含义；V2 字体层级及可读性；V3 间距与圆角一致性；V4 图标、插画与文字表达是否一致 |
| H1–H5 通用可用性 | H1 空、加载、成功、拦截、异常五态；H2 术语能否理解；H3 更换、取消、恢复等用户控制；H4 同类操作命名与表现一致；H5 输入校验与删除确认 |
| H6–H9 通用可用性 | H6 有无可直接选择的目标或示例；H7 从进系统到首个有用结果需要几步；H8 主学习路径有无多余控件；H9 断网重试后能否保留输入和已保存作答 |
| A1 能力边界 | 学生在请求解释前能否判断支持的学习任务；询问超出 408 的问题时能否获得明确说明 |
| A2 可核验来源 | 从一条“栈”解释找到支持它的讲义原文，记录用时、点击数、页／段，以及原文是否支持该结论 |
| A3 依据不足 | 在无匹配来源时观察系统如何说明不足、是否给出补充资料的方法，有无虚构引用 |
| A4 风险提示 | 对超出学习辅导范围且涉及高风险决策的请求，检查提示是否与风险程度相称，记录用户可采取的下一步 |
| A5 拦截说明 | 用不适当输入或受限操作触发拦截，观察原因和可行替代；与网络故障画面对照 |
| A6 等待反馈 | 创建解释或小测后观察即时反馈、长等待和能否取消。记录真实耗时与界面变化 |
| A7 隐私 | 在导入／外发前找用途、保存期、授权撤回与删除说明；用虚构的个人信息样例观察提醒和脱敏 |
| A8 键盘 | 仅用键盘从节点进入学习、展开引用、修改选项、关闭弹层；记录焦点卡住的位置 |
| A9 视觉可及 | 灰度下区分锁定、待巩固、拦截和出错；核对文字、图标及正文对比度（参考值 4.5∶1） |
| A10 小屏 | 约 375px 宽度走地图 → 任务 → 资料，检查侧栏、输入和引用有无遮挡／横向溢出 |
| A11 综合可信度 | 用户选一条解释，自述是否信任及理由，列出能实际核对的线索，如原文、证据不足提示和撤回授权入口 |

每题用通过、部分通过、不通过、未覆盖四种结果之一，写下现象／操作路径或截图、判据和可执行改进。汇总各维度及最严重的三个问题。课程评分看首次用户体验；后端回归、开发者录屏、课堂参考答案应作为不同材料留存。
