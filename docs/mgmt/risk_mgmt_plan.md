# 项目风险管理计划

## 1. 目的与范围

本计划用于识别、评估、应对和跟踪影响项目范围、进度、质量、技术可行性和演示交付的风险。适用于需求分析、方案设计、实现、测试、演示和最终交付全过程。

## 2. 风险管理原则

- 风险在发现时登记，不等到造成问题后再补记。
- 优先处理高概率、高影响和临近触发窗口的风险。
- 每项高风险必须有明确责任人、触发条件和应对动作。
- 风险关闭必须有验证证据，风险转化为问题后进入问题跟踪流程。
- 风险应对以保护关键里程碑和核心交付价值为优先。

## 3. 角色与责任

| 角色 | 主要责任 |
| --- | --- |
| 项目负责人 | 维护风险台账，组织评估，推动应对和升级 |
| 各工作负责人 | 识别所属领域风险，执行应对措施，及时更新状态 |
| 指导教师/项目发起人 | 审批重大范围、资源和优先级取舍 |
| 测试/评审负责人 | 提供质量风险证据，验证缓解措施效果 |

## 4. 识别与评估流程

1. 在周例会、需求评审、设计评审、测试和发布准备中识别风险。
2. 为每项风险记录描述、原因、影响、触发条件、责任人和应对措施。
3. 按概率和影响分别取 1–5 分，计算风险值 `R = 概率 × 影响`。
4. 按风险值确定优先级，并在每周同步或事件触发时复评。

| 风险值 | 优先级 | 处理要求 |
| --- | --- | --- |
| 15–25 | 高 | 立即制定应对方案，项目负责人持续跟踪，必要时升级 |
| 8–14 | 中 | 指定责任人和截止时间，至少每周复核 |
| 1–7 | 低 | 记录并在例行检查中观察 |

概率与影响评分均按以下口径执行：1 表示很低，2 表示较低，3 表示中等，4 表示较高，5 表示很高。影响评分应综合考虑范围、进度、质量和交付承诺。

## 5. 风险应对策略

- **规避**：调整方案或范围，消除风险来源。
- **减轻**：降低发生概率或发生后的影响，例如提前验证、拆分交付和增加检查点。
- **转移**：将风险交由更适合的责任方或外部服务承担，并明确接口与验收条件。
- **接受**：当处理成本高于预期损失时保留风险，同时设置监控指标和触发后的行动。

## 7. 监控与报告

- 项目负责人每周更新风险值、状态和下一步动作。
- 高风险在每次进度同步中单独报告，直到降为中风险或关闭。
- 当风险实际发生时，立即转为问题，记录影响、临时措施、最终解决方案和复盘结论。
- 里程碑评审前检查是否存在未评估风险、逾期应对措施或缺少验证证据的已关闭风险。
- 交付完成后复盘风险登记表，保留可复用的预防措施和经验。

## 8. 变更与维护

风险管理计划在项目范围、技术路线、交付日期、团队分工或外部依赖发生重大变化时更新。每次更新应记录日期、变更原因和批准人。
