## 演示情境与教育学说明

录制前通过 API 在独立演示库完成“线性结构基础”的三题诊断，并建立仅面向“栈的理解”的诊断轮次，之后的演示作答、接受任务、资料复习与复测均通过真实页面完成。原有用户数据库未被修改。

| 画面阶段 | 实际操作与结果 | 对应概念及边界 |
| --- | --- | --- |
| 先修与起点 | 线性结构已有证据，栈尚为证据不足 | 知识空间的先修约束思路；当前实现是先修图规则，未完成完整状态族与概率推断 |
| 单题理解 | 理解题答对 1 题，仍显示证据不足 | 多题证据诊断；单题结果不作为稳定掌握结论 |
| 转入应用 | 理解题 3/3，应用尚无证据，系统推荐应用任务 | 布鲁姆认知过程维度用于任务目标与选题；标签描述题目要求，不等于难度或学生能力等级 |
| 暴露困难 | 预设应用题 0/3，显示判分与解析，下一安排回看理解资料 | 体现形成性评价中“收集表现—反馈—调整”的思路；当前为规则驱动，未实施专业错因模型 |
| 资料复习 | 完成阅读，证据仍为 6 题 | 学习行为与表现证据分开保存；阅读不直接转成掌握分数 |
| 新题复测 | 应用练习使用 `wf_stack_a1..a3`，复测使用 `wf_stack_b1..b3`；新一轮应用题 3/3 | 重新收集相关维度的证据，减少重复原题记忆干扰；并非正式前后测实验 |
| 状态更新 | 理解与应用分别有 3 题支持，记忆和分析仍显示证据不足 | 分维度报告，保留尚未覆盖的部分，不作总体认知等级认证 |

3 题、80%、近期两道不同应用/分析题错误后回看资料，以及复测证据边界，均为可评审的原型参数。先修图、标签和证据实际参与系统决策；本演示不证明诊断效度或学习收益。

## 素材与剪辑方式

通过应用浏览器截图接口以约 5 fps 逐帧采集实际操作，按操作片段剪辑、调整阅读节奏后编码；保留画面中的题目、结果和真实任务状态。左侧为实机画面，右侧为后期添加的概念解读和阶段指示。未通过重绘页面、替换分数或合成状态来制作结果；剪除了一个未切换成功的导航等待片段。无配音。

GIF 用于 GitHub README 自动播放，MP4 用于清晰查看。原始逐帧素材和演示数据库留在本地工作目录，不将数据库、会话令牌或个人资料提交到仓库。可通过本项目正常启动步骤复现学习路径；演示初始化使用显式 `--demo --design-flow` 种子和独立数据库。
