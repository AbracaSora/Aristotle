前一版的 `final_tests.py` 将领取生成任务、校验模型输出、整卷判分、评语和恢复放在同一文件。现在 `final_generation.py` 负责出卷，`final_papers.py` 负责试卷和判分，`final_tests.py` 保留反馈处理和 worker 命令。三个文件都纳入核心分支覆盖检查。

## 交卷时间与反馈历史

重构前，练习查询只有本人条件。恢复第一张卷的评语时，后做的三道其他知识点练习和第二张试卷的两道题能占满全部五条历史记录。

```python
.where(Attempt.user_id == user_id)
```

重构后，先在查询中过滤时间，再取有界条数。历史试卷的筛选同样使用本卷交卷时间。对时间相同且无法判断先后的记录，按不进入历史处理。排序使用数值时间戳，返回时再转为 UTC 文本。

```python
.where(Attempt.user_id == user_id, Attempt.created_at < paper.submitted_at)
```

## 第 21 份评语与迟到的出卷结果

旧查询先从全部 pending 记录中取 20 条，随后在 Python 检查领取时间。如果这 20 条都由其他任务处理，第 21 条即使从未领取也没有机会被发现。新查询先判定领取条件，然后再排序和限量。

```python
or_(claimed.is_(None), claimed < now - 1800)
```

二次领取由原子状态检查保护。用模拟模型在出卷请求途中触发超时恢复，再分别返回有效试卷和 HTTP 503。检查持久化的中断错误、空试卷和一次调用计数，两条路径均不得覆盖恢复结果。评语另测两种降级。账号在反馈启动前已转为维护者时，模拟服务收到零个请求；反馈任务超时恢复后才返回模型建议时，规则建议和中断标记保留。两项都比对交卷时的分数和掌握事件。所有复现使用测试账号、自编题和进程内模型响应。[修复前的两个失败用例](before.txt) · [本轮集成用例](../../../../tests/integration/test_curriculum_contract.py)
