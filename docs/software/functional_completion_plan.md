# 功能补完讨论稿：知识地图、资料检索与 LLM

更新：2026-11-08。基于既有功能需求与现有实现，供下一轮讨论；本文不是新增模块的实现或验收记录。PostgreSQL 适配及实际运行边界见 [数据库迁移](postgresql_migration.md)。

## 本轮实现更新

以下保留讨论时的方案。当前已实现先修关系地图及侧栏学习流程、pgvector 来源索引/语义查询、真实模型候选标注与引用解释、授权撤销传播和持久化任务；数据库 revision 为 `0002_semantic_learning`。稳定知识点/边的规范化表、真实 PDF、检索质量及教学效果评测仍待补完。实现与实际验证状态以 [学习空间实现](learning_space_implementation.md) 为准，不能把下文“建议”整体视为验收通过。

## 1. 以学习过程作为主界面

建议把知识地图作为学习空间的主要视图：学生看到当前范围、知识关系、已有证据和适合继续学习的位置；点击某个知识点后，在同一空间内打开解释、材料与任务。管理、导入、审核等工具仍可有独立入口，学生的主要流程不需要依次切换一排模块卡片。

围绕“栈”的一次使用：

1. 地图显示“线性结构 → 栈 → 栈操作”等已审核先修关系，突出当前知识点和推荐下一步。
2. 点击“栈”，展开记忆、理解、应用、分析四个维度的证据数量、近期表现和不确定性；图节点的颜色与维度详情使用可解释的图例。
3. 理解证据较充分而应用证据不足，点击推荐路标进入操作推演任务。
4. 应用困难后，保留地图位置，展示与该目标相关的公共资料或本人已确认讲义，并标明来源页码/段落；LLM 可基于来源辅助解释。
5. 阅读结束仍保持原证据状态；用另一组应用题复测，再更新地图上的证据及推荐方向。

地图应支持缩放、拖拽、搜索定位、范围收起/展开和聚焦当前路径；初始视图使用稳定的分层布局，避免每次刷新节点随机跳动。手机可使用聚焦单个知识点的前后关系视图，并提供可键盘访问的关系列表。

布鲁姆标签决定任务要求和维度证据，不画成所有学生必须逐级攀爬的六级台阶。未掌握、证据不足与先修暂未满足需要分别表达；节点状态不作能力认证。先修关系与语义相似关系使用不同含义，检索相近不能自动建立先修边。

## 2. 知识地图的数据基础

现有图版本中的 JSON 快照能支撑原型，但地图编辑、跨章节引用与资料关联增加后，建议新增稳定知识点实体和版本化关系表，再保留发布快照作为学习任务的依据：

| 数据 | 建议约束 |
| --- | --- |
| 知识点、学科与章节 | 稳定 ID 与显示层级分开；变更名称不更换知识点身份 |
| 图版本及版本内节点 | 已发布版本只读，新版本审核后发布；任务绑定当时版本 |
| 先修边 | 两端属于同一有效版本、无悬空点、无环；保留维护依据 |
| 题目—知识点关联 | 支持以后一个题目覆盖多个知识点；明确主要知识点与证据归属，避免一次作答无差别提高多个节点 |
| 片段—知识点关联 | 保留候选、人工确认、撤销、版本及来源位置；候选不能直接进入个人学习推荐 |
| 学生证据覆盖 | 从有效作答计算并保留策略版本；需要加速时再引入可重建的派生状态 |

发布的知识结构、学生当下证据和界面布局是三类数据：地图布局不决定掌握状态，LLM 也不拥有发布先修边或直接写学习状态的权限。上述结构调整应另写 Alembic revision，本次数据库引擎切换仍保留现有业务结构。

## 3. 语义检索作为资料能力

建议在 PostgreSQL 上后续增加 pgvector，优先处理“针对当前知识点和任务，找出相关且有权使用的资料片段”。目前没有 embedding 字段或语义索引，已有 `source_chunks` 仅做知识点关联查询。

处理链：上传/粘贴 → 抽取与分页 → 分段 → 知识点候选关联 → 学生确认 → 建立有效检索索引 → 检索并引用。分段数据应保留资料 ID、所有者、页码或段落位置、正文 hash、解析版本；向量索引另记 embedding 模型、维度和生成版本。切换模型不能混用不同向量空间。

检索同时考虑文本关键词、语义相似与当前认知目标。检索前限定公共已发布内容或本人未删除且已确认的片段；返回正文前再核对来源权限，撤销或删除后立即停止引用，派生索引和备份按需求清理。向量索引作为可重建派生数据，不承载资料所有权的唯一记录。

验收需准备一组知识点/任务与相关来源片段的标注样例，检查召回和排序、引用定位、无匹配时的提示、跨用户隔离及删除后的不可检索性；不能只用“返回了几段文本”认定有效。

## 4. LLM 接入的顺序与边界

建议先接需求中已有的内容标注，再接基于资料的解释，最后完善自然语言任务组织。供应商、模型、部署方式与 embedding 模型需要结合团队资源确定，本文不预设某一家供应商，也不发起付费调用。

| 用途 | 输入与输出 | 必须保留的边界 |
| --- | --- | --- |
| 认知标注 | 完整题目版本、答案解析、分类规则 → 候选标签、理由、歧义与置信度 | 校验题目版本和输出结构，人工审核后发布；保留模型、提示模板、规则版本和用量 |
| 辅助解释 | 当前题目、已经提交的答案、允许使用的来源 → 有引用的解释 | 客观题由程序判分；不能提前泄露未作答题目的答案，材料不足时说明证据不足 |
| 学习任务组织 | 学生目标、当前状态、可用工具 → 调用诊断、检索、推荐并解释结果 | 任务接受、作答、状态更新及内容发布仍经后端权限和业务规则 |

真实任务需有后台 worker、超时/重试、并发配额、费用记录和失败降级。当前模拟 job 的手动 `/run` 和进程锁不能视为生产任务系统；同一内容版本的相同标注配置应复用或明确新建，不能覆盖历史。

外部发送私人资料前取得同意；拒绝外传时仍可使用公共题库和规则学习路径。保留公共静态解析与规则推荐，让外部模型失败不阻断基本学习。

## 5. 建议讨论和实现次序

1. 真实 PostgreSQL 的旧数据导入、原有闭环集成测试和迁移持久化检查已完成（2026-11-08）；常驻服务启动及浏览器体验另行核对，证据见数据库迁移说明。
2. 确定地图的默认视图、关系语义、节点状态和点击后的学习流程，先用现有审核样例走通“栈”的完整过程。
3. 确定稳定知识点/先修边和来源片段的数据契约，再迁移知识结构并实现地图 API。
4. 落实真实 PDF/来源片段，再接 embedding 与检索；同步测试权限与删除传播。
5. 接入 LLM 标注与审核，再接检索解释和任务组织；分别测标签质量、来源支持度、任务成功率和学习效果。

需要讨论的选择：地图更侧重“浏览知识关系”还是“沿推荐路径学习”（建议后者作为默认，保留全图浏览）；首版章节范围；可用模型供应商及隐私条件；正式题库和讲义样本。它们影响后续界面与接口，不需要先堆叠多个数据库服务。
