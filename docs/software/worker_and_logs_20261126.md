# 资料自动导入与运行日志补完

更新：2026-11-26。本轮补上资料自动worker、抽取进程隔离、中断/过期回收和运行日志。此前手动run接口保留，和worker共用同一套领取/完成逻辑。

## 运行

```bash
uv run python -m aristotle_backend.import_worker
# 单次领取，处理一项或发现队列为空后退出
uv run python -m aristotle_backend.import_worker --once
```

`uv run python scripts/run_learning_space.py` 现会一并启动资料worker、model_jobs和final_tests；Ctrl-C只停止本次子进程，数据库卷保留。已有服务不会被自动重启；应通过自己的启动终端重启新版启动脚本才能带起这些worker。状态文件记录worker PID，任一子进程退出时整组会结束并执行清理。

## 资料任务状态与资源边界

1. 上传先校验身份、范围、文件头和20MB限制，保存queued任务即返回202，不在上传请求中解析PDF。
2. 任务冻结学习范围、知识点集合和图版本。旧任务缺少快照时按既有范围兼容处理，不捏造当时不存在的元数据。
3. worker只自动领取真实text/pdf，显式pdf_mock仍需模拟入口运行。事务行锁和CAS领取，多个进程不能重复导入。
4. 抽取前关闭读取事务；PDF字节经stdin送入独立Python进程。子进程不继承模型服务配置，单项30秒墙钟上限、30秒CPU上限；Linux另限512MiB地址空间。**macOS不宣称有同等地址空间硬限制**，仍有进程/CPU/墙钟边界。
5. 抽取继续执行100页、总文本100万字符等限制。保留页码，名称匹配给候选，未确认资料不进入有效推荐/私人检索，不调用付费模型。
6. 保存前重新检查角色、范围及领取标识；成绩、掌握状态和正式公共内容都不受资料导入直接更改。
7. 完成/失败清理任务中的PDF原始字节。运行超过60秒视为中断，排队超过24小时视为过期；每次最多回收100条，不做无界全表加载。回收标记失败并要求重新上传，不静默重放。

输入太大/损坏/加密/扫描件、进程异常或超时都会留下可查询失败状态。日志记录job ID和错误码，不写完整讲义。OCR仍不支持。

## 日志

API、模型任务、小测和资料worker均接入 `.local/logs/aristotle-<service>-<pid>.log`。每个文件上限1MiB，轮转保留3份，启动时清理本工具14天前的旧日志；文件与轮转新文件均为600权限。按进程分文件，避免多个进程争用同一轮转文件。

日志formatter对Bearer凭据、常见sk密钥和数据库URL密码脱敏；这不允许调用方记录私人正文，代码仍只记录ID、状态和错误码。生产集中日志、跨主机留存与告警尚未配置。

## 验证与边界

- 实现前4项worker用例失败；实现后领取防重、自动完成、权限撤回、解析超时、中断/过期恢复、模拟队列隔离、入口单次执行、原始PDF清理均有行为断言。
- Linux内存限制用配置路径测试；实际macOS执行不冒充Linux部署性能。真实PDF子进程、页码及加密拒绝均经过运行测试。
- 本轮新增worker及相关既有流程在真实PostgreSQL上93项通过；完整质量门禁结果在执行完成后追加。
- 尚需20份有代表性的授权PDF做P95/内存峰值测试、进程级部署压测与备份恢复演练。微型自编PDF夹具不是正式PDF性能验收。

## 最终结果

本轮最终后端185项通过、1项PG专用用例在SQLite路径跳过；另在真实PG上两组相关回归93项、27项通过（部分重叠）。完整原始日志归档于 `quality_evidence/completion_20261126/`。类型、编译、Ruff、Pylint错误检查、依赖审计和核心覆盖门禁均通过；严格结构门禁尚未通过。

## 生产配置保护

`.env.example`增加 `ARISTOTLE_ENV=development`。正式部署必须显式设为 `production`，使用非默认、至少12字符的数据库口令与PostgreSQL；所有演示导入入口均拒绝生产模式。API启动还检查已有演示账户是否沿用公开默认口令，发现后拒绝启动；这不会自动修改或删除用户账号。

本轮未将本机演示环境切成production，也没有替用户更改密钥。环境防护代码通过不代表HTTPS、备份恢复和正式内容人工审核已验收。
