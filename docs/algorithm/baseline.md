# 后端规则基线 baseline-0.1

状态：可执行原型规则，尚无诊断效度或学习收益验证。源码位于 `code/core_engine/aristotle_core/policy.py`，纯函数不读取数据库、不调用模型。

## 证据更新

1. 服务层排除未发布或已停用的题目版本；保留全部历史，但不将无效内容用于当前诊断。
2. 选取 `[当前时间−14 天, 当前时间]` 的有效作答，按时间和记录 ID 排序。
3. 按稳定 `question_id` 取窗口内首次有效作答；重复练习、新内容版本不直接增加独立题数。
4. 以知识点汇总题数、正确率；再按“知识点 × 认知标签”分别汇总数量、正确率和最近证据时间。
5. 按知识图拓扑顺序计算：少于 3 题为 `insufficient`；至少 3 题且正确率 ≥ 0.8、全部直接先修均 `provisional`，才是 `provisional`；其余为 `needs_review`。

认知维度不足 3 题则标记证据不足；不输出学生的总体布鲁姆等级。根节点没有先修，先修条件视为满足。当前纯规则只实现先修 DAG 约束，没有实现完整知识空间的状态族或概率推断。

## 选题

排除先修未满足的知识点，只从已发布的题目中选择；同稳定题目 ID 仅考虑最新已发布版本。首版只分配 remember/understand/apply/analyze 标签。

知识点优先级依次为：待巩固、证据不足、初步掌握。同状态先补当前库存中认知维度的缺口，再优先最近较少练习的知识点。知识点内优先补证据不足或正确率低的可用标签；题目按最近作答时间排序，未练优先，再选最久未练的，最多 3 道。

显式请求目标知识点也不能绕过先修。指定标签无题时保持标签并告知内容不足；不替换成别的认知活动。少于 3 题明确显示短关卡告警；没有题时仅引用本人已确认的关联资料，没有资料则返回 `content_unavailable`。

每次任务保存策略版本、知识图版本、选择结果和证据摘要。私人资料只保存引用，不把正文放进快照；删除、取消关联或改变关联后，历史查询也会停止显示原文。

## 演示范围与后续

3 个知识点按“线性结构基础 → 栈的概念 → 栈操作与分析”连接；12 道演示题只用于验证流程。初始诊断为分阶段补证据，和练习共享 14 天窗口；独立诊断轮次、目标认知困难后的细化回退、策略参数配置和效果比较尚未实现。

阈值来自需求初稿，不是已经证明可靠的教育测量结论。变更阈值、窗口、证据去重或排序规则时，应更新策略版本并补对应的固定场景测试。
