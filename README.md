# Aristotle 408

面向计算机 408 备考大学生的自适应学习 Agent，帮助学生明确「哪些知识还没掌握，下一步应该学什么」。

本项目是[智能软件工程实践课程](https://github.com/bettermorn/IntelligentSWEPractice)的小组实践作品。目前处于需求分析与方案设计阶段，仓库已建立文档和代码目录，以下功能均为开发规划。

## 产品定位

408 备考覆盖数据结构、计算机组成原理、操作系统和计算机网络。针对薄弱点不清、复习路径固定、个人讲义与练习脱节的问题，Aristotle 408 计划结合知识空间理论诊断掌握状态，自适应推荐学习内容与练习，并以多邻国式短关卡组织复习。产品的重点是让学习路径随作答反馈持续调整。

首批计划邀请 **30—50 名学生**试用，首版暂定于 **2026 年 12 月**发布，具体范围与日期随课程排期和开发进度调整。完整背景、5W1H 分析和评估方式见[问题定义与产品描述](docs/requirements/problem_definition.md)。

## 首版规划

先以**数据结构的部分章节**验证完整学习流程，再逐步扩展至其他科目；具体章节在需求分析阶段确定。

| 能力 | 首版计划 |
| --- | --- |
| 知识诊断 | 结合知识点、先修关系和多次作答，估计掌握状态与薄弱点 |
| 自适应推荐 | 根据当前状态推荐可学习的知识点、练习和复习任务，并说明推荐理由 |
| 个人资料 | 支持文本型 PDF 或粘贴讲义，将内容关联到预设知识点，保留来源位置 |
| 短关卡学习 | 提供客观题练习、即时反馈和答案解释，控制单次任务规模 |
| 学习记录 | 保存作答与进度，在后续学习中更新诊断和推荐 |

学习流程：**选择范围或上传讲义 → 初始诊断 → 推荐任务 → 关卡学习与反馈 → 更新知识状态 → 下一轮复习**。

首版暂不覆盖全部 408 题型、扫描件识别、复杂主观题自动评分和社交排行榜。

## 自适应学习思路

- **知识空间**：依据知识点及先修关系约束可能的掌握状态，识别当前状态下适合继续学习的内容；不将一次答错直接等同于未掌握。
- **推荐策略**：先实现可解释的规则基线，综合知识缺口、先修条件与复习记录安排任务，再通过试用比较和改进策略。
- **Agent 职责**：调用资料检索、诊断和推荐工具，组织学习任务并生成解释；判分、状态存储和策略约束由程序执行。生成内容需核对资料依据与答案质量。

使用独立测评题检查诊断效果，并记录薄弱点前后测表现、关卡完成情况与用户反馈。学习收益需通过评估验证，不以关卡进度代替掌握程度。

## 仓库结构

沿用课程建议的文档、代码、测试分层结构：

```text
.
├── docs/
│   ├── requirements/     # 问题定义、需求规格、用户故事与验收标准

│   ├── software/         # 原型、系统架构与接口设计
│   ├── mgmt/             # 分工、沟通与风险管理

│   ├── frontend/         # 学习界面与交互
│   ├── backend/          # API、资料处理与数据存储
│   └── core_engine/      # 可独立测试的诊断与推荐逻辑
└── tests/
    ├── unit/             # 单元测试
    └── integration/      # 集成测试
```

## 开发里程碑

以下周次对应课程的 17 周安排，具体日历日期以课程进度为准。

| 阶段 | 课程周次 | 主要交付 |
| --- | --- | --- |
| 分析 | 第 1—2 周 | 用户调研、问题定义、功能与非功能需求 |
| 设计 | 第 3—6 周 | 用户故事、交互原型、理论调研、技术方案及沟通和风险计划 |
| 开发 | 第 7—10 周 | 资料处理、诊断、推荐与短关卡的完整流程，代码质量检查 |
| 测试 | 第 11—13 周 | 单元与集成测试、内容质量检查、小组交叉测试及缺陷修复 |
| 发布与迭代 | 第 14—17 周 | 部署、试用反馈、迭代复盘与作品答辩 |

## 团队协作与开发说明

团队按前端体验、后端服务、学习引擎、测试与集成划分工作，具体负责人在项目管理文档中维护。使用 Issue 跟踪任务，通过分支和 Pull Request 提交变更，经评审后合并；功能变更同步更新相关文档和测试。

技术选型、安装与运行步骤将在首个可运行版本完成后补充。当前仓库尚无可启动的应用。开发中使用脱敏或获授权的样例资料，个人讲义、账号密钥及模型 API 凭据不提交到仓库。
