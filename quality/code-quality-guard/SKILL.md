# 项目质量护栏

本文件是课程 CodeQualitySkill v2 的项目适配，不是原文复制。来源与下载内容hash见 `source.json`；完整团队评审模板在 `code_review_template.md`。

## 工作流程

1. 编码前读取需求、版本契约和调用方，确定检查范围及有行为断言的回归用例。
2. 写代码时限制职责、函数尺寸、嵌套和参数；外部输入集中校验、资源作用域关闭、事务不跨无界外部I/O。
3. 修复顺序：运行/数据安全阻断、吞异常与并发等严重缺陷、结构与重复、可读性。每次小改后回归。
4. 用 `uv run python scripts/check_guardrails.py --full` 执行扫描、类型、测试、覆盖与安全检查；工具失败同样阻断。所有检查输出保存在 `.local/guardrails/`，CI保存artifact。
5. 按模板逐项填真实结果。静态诊断不是已证实业务Bug，综合覆盖不是分支覆盖；SQLite不替代PostgreSQL，MockTransport不替代真实模型，AI自审不替代人工。
6. 每个评审单元最多自动修复三轮；仍失败时列出位置、指标、修复与阻塞原因，不私自豁免。用户授权继续工作时可开始下一个明确的评审单元。

## 严格阈值

| ID | 指标 | 门槛 | 检查 |
|---|---|---|---|
| TH-01 | 函数有效行 | ≤40 | AST函数体排除空白/注释/嵌套函数定义体 |
| TH-02 | 圈复杂度 | ≤10 | Radon |
| TH-03 | 认知复杂度 | ≤15 | cognitive-complexity；工具度量注明口径，不冒充Sonar |
| TH-04 | 控制流嵌套 | ≤3 | AST，嵌套函数分别计算 |
| TH-05 | 形参 | ≤4 | 含依赖注入及仅关键字参数，不静默豁免框架 |
| TH-06 | 文件行数 | ≤400 | Python源文件物理行数 |
| TH-07 | if布尔子项 | ≤3 | AST BoolOp叶子数 |
| TH-08 | 重复块 | ≥6行块为0 | jscpd，token阈值50，工具口径另保留 |
| TH-09 | 新增/修改行覆盖 | ≥80% | 当前HEAD到工作区含未跟踪Python源码，不只看已提交diff |
| TH-10 | 编译/静态/类型 | 错误0 | compileall、Ruff、Pylint、mypy；警告保留，不自动宣称全部无警告 |
| TH-11 | 评审diff规模 | ≤400行 | tracked diff与未跟踪代码合并统计；超限提示拆评审单元 |
| TH-12 | 模块导入环 | 0 | 项目内静态导入图；动态导入单列未知 |
| TH-13 | TODO/FIXME | 必须有编号 | 本地SM/ISSUE编号须能在评审清单中定位 |
| TH-14 | 依赖/密钥风险 | 0未处理问题 | pip-audit、detect-secrets；不将忽略文件中的.env发送/打印 |

补充项目要求：核心判分、证据、推荐、版本与输出校验文件的分支覆盖逐文件≥80%。本地hook不要求Docker启动；完整CI跑独立PostgreSQL数据库。正式业务迁移必须隔离测试通过后执行并核对旧表行数。

## 人工边界

启发式规则的测量效度、正式内容审核、真实模型质量、人工评审签字和部署审批需要实际证据。缺少材料时记录阻塞，不生成虚构内容。

## 使用与安装

Codex读取根AGENTS.md即可找到本技能，无需写入用户全局目录。其他支持SKILL的工具可选择本目录。`uv run pre-commit install` 安装本地hook；`uv run pre-commit run --all-files` 手动复核。不使用 `--no-verify` 跳过失败。

## 合并交付的评审包

单个提交累计超过 400 行时，护栏从当次比较基线重放 `quality/backend-review.zip`。每批的 Git 增删行和 TH-11 计数均须达标，最终源码目录须与交付逐文件一致。变更行覆盖继续以整份提交计算。日常提交使用 HEAD 作为基线，CI 使用推送前或 PR 的基线提交。
